# Adaptive parameters in read aligners and what they do to determinism (prior art for an adaptive CERTA)

Scope: how existing short-/long-read aligners tune parameters at run time or per sample from data they observe, how they keep or lose deterministic output, and what could carry over to an exact, certified aligner (CERTA). Research date: 2026-10-23. Years are publication/release years. Where I could only reach a secondary source (forum, aggregator), this is flagged.

## Q1. BWA-MEM's per-batch insert-size estimation and -K; cross-read state in bwa-mem2, minimap2, Bowtie2, strobealign and others; how they document reproducibility

### Takeaway
BWA-MEM is the canonical example of cross-read adaptive state that breaks thread-count invariance: it infers pair orientation and the insert-size distribution from each batch of reads, and the default batch size is 10 Mbp x nThreads, so changing `-t` changes the batches, the estimates and (slightly) the output. `-K INT` fixes the batch size in input bases independent of threads and is the documented reproducibility fix (CCDG uses `-K 100000000`). Other tools avoid the problem in different ways: Bowtie2 and minimap2 keep no data-estimated pairing state (fixed `-I/-X`, `-F`) and seed tie-breaking per read; strobealign resets its insert-size estimator at fixed, input-defined chunk boundaries and seeds its RNG per chunk; DRAGEN samples once at start and then freezes; BBMap (per a forum post) keeps per-thread running averages and is nondeterministic.

### Cited Findings
**BWA / BWA-MEM (lh3/bwa)**
- Man page, `bwa mem` DESCRIPTION: in paired-end mode, mem infers the read orientation and the insert-size distribution "from a batch of reads." — [bwa.1 man page](https://github.com/lh3/bwa/blob/master/bwa.1)
- `-K INT`: "Process INT input bases in each batch regardless of the number of threads in use [10000000*nThreads]." By default the batch size is proportional to threads; because the inferred insert-size distribution slightly depends on batch size, different thread counts may give different output; specifying `-K` "helps reproducibility." This is the only reproducibility statement in the man page. — [bwa.1 man page](https://github.com/lh3/bwa/blob/master/bwa.1)
- `-I`: user can supply mean, sd (default 10% of mean), max (default mean+4 sigma) and min of the insert-size distribution, only for FR orientation; by default BWA-MEM infers these and pair orientations "given enough reads." — [bwa.1 man page](https://github.com/lh3/bwa/blob/master/bwa.1)
- Older `bwa sampe` (aln) algorithm, same man page: insert size estimated per 256*1024 read pairs, from pairs with both ends mapped at single-end quality >= 20, mean/variance from pairs within [Q1-2(Q3-Q1), Q3+2(Q3-Q1)]; maximum proper-pair distance solved from the fitted distribution. — [bwa.1 man page](https://github.com/lh3/bwa/blob/master/bwa.1)
- History: BWA-MEM "automatically infers pair orientation from a batch of single-end alignments" (0.7.0, Feb 2013); user-specified insert-size distribution allowed from 0.7.8 (Mar 2014); 0.7.15 (May 2016) fixed a long-standing bug that could underestimate the insert-size upper bound; 0.7.19 (Mar 2025) states output identical to 0.7.17/0.7.18. NEWS.md never mentions `-K`. — [bwa NEWS.md](https://github.com/lh3/bwa/blob/master/NEWS.md)
- GitHub issue #121 (24 Apr 2017, bwa 0.7.15): user saw different SAM output at `-t 2/6/10/16` but identical output when re-running at the same thread count; diagnosed `mem_pestat` running on a per-batch sample whose size scales with threads. Heng Li (25 Apr 2017): the bwa-mem result does change with the number of threads; use a large `-K` such as `-K 10000000` for stable results regardless of threads. — [lh3/bwa issue #121](https://github.com/lh3/bwa/issues/121)
- Secondary (Biostars, page returned 403 to me; content via search summary): Heng Li reportedly explained that BWA-MEM uses no RNG; it hashes deterministic information so the i-th input read always gets the same hash, hence reordering the FASTQ breaks determinism; run-to-run differences come from insert-size estimates differing between batches and from placement of repetitive hits. — [Biostars 238637](https://www.biostars.org/p/238637) (unverified directly); see also [Biostars 90390](https://www.biostars.org/p/90390)
- NEWS: random choice among equally best hits for repetitive reads dates to 0.5.9rc1 (2010); 0.7.6 (2014) fixed non-random distribution of repetitive single-end hits. — [bwa NEWS.md](https://github.com/lh3/bwa/blob/master/NEWS.md)
- CCDG pipeline standard (basis of Regier et al., Nat Commun 2018, "Functional equivalence of genome sequencing analysis pipelines..."): BWA-MEM 0.7.15; "Use `-K 100000000` to achieve deterministic alignment results (Note: this is a hidden option)"; plus `-Y`, no `-M`. — [CCDG PipelineStandard.md](https://github.com/CCDG/Pipeline-Standardization/blob/master/PipelineStandard.md); [Regier et al. 2018 record](https://ideas.repec.org/a/nat/natcom/v9y2018i1d10.1038_s41467-018-06159-4.html)

**bwa-mem2 and derivatives**
- bwa-mem2 (Vasimuddin, Misra, Li, Aluru, IPDPS 2019): "produces alignment identical to bwa," output should match bwa-mem 0.7.17; ~1.3-3.1x faster. The ERT index mode recommends `-K 1000000` "to see the speedups"; LISA mode "accelerates seeding ... by up to 4.5x" with "exact same output as bwa-mem2." No determinism statements beyond identity. — [bwa-mem2 README](https://github.com/bwa-mem2/bwa-mem2)
- bwa-mem3 (fg-labs, docs re-measured 2026-07): "`mem_pestat` estimates the paired-end insert-size distribution from whatever reads happen to land in a batch"; default batch size is `chunk_size x -t`; "`-K` pins the batch target for reproducible partitioning"; "any equivalence claim on this page is implicitly a claim at a fixed batch size"; at fixed `-K`, output identical at `-t 1/7/16` on a 5M-pair WES slice; CI script `thread_determinism.sh` checks `-t 1/3/4`. It also makes tie resolution deterministic. A known SIMD-dependent difference: a phantom `XS` tag differs between AVX2 and AVX-512BW/NEON builds due to unzeroed query padding (issue #290, open). — [bwa-mem3 equivalence docs](https://bwa-mem3.readthedocs.io/en/latest/whats-different/equivalence.html)
- NVIDIA Parabricks fq2bam (GPU BWA-MEM): claims output should match bwa-0.7.15 + GATK4 but lists sources of difference; in paired-end mode the `-K` chunk size "can cause small mismatches," fixed by passing the same `-K 10000000` to both; also PA-tag placement/rounding and unmapped-read ordering differ. — [Parabricks fq2bam docs](https://docs.nvidia.com/clara/parabricks/latest/Documentation/ToolDocs/man_fq2bam.html)

**minimap2**
- `-K NUM`: number of query bases loaded per mini-batch [500M]; larger helps load balancing at the cost of memory. The default is a constant, not thread-scaled. — [minimap2.1 man page](https://github.com/lh3/minimap2/blob/master/minimap2.1)
- Paired-end pairing code (`pe.c`) estimates no insert-size distribution: pairing uses a fixed `max_gap_ref` and `pe_bonus` passed in from options, and operates on one pair's regions at a time (no cross-read state). — [minimap2 pe.c](https://github.com/lh3/minimap2/blob/master/pe.c)
- `--seed INT`: minimap2 hashes INT and the read name when choosing between equally best hits; `--no-hash-name` makes identical sequences get the same alignment regardless of name. — [minimap2.1 man page](https://github.com/lh3/minimap2/blob/master/minimap2.1)
- Data-dependent parameters: `-f` (ignore top fraction of frequent minimizers, default 0.0002) is estimated from the reference, bounded by `-U`; `--q-occ-frac` discards query minimizers by occurrence within the query; in short-read mode a second round of chaining with a higher occurrence threshold is run "if no good chain is found" (per-read fallback). `-I` splits the index into parts and the page warns mapping quality is incorrect with a multi-part index. — [minimap2.1 man page](https://github.com/lh3/minimap2/blob/master/minimap2.1)

**Bowtie2**
- PRNG is re-initialized for every read with a seed that is a function of read name, nucleotide string, quality string and `--seed` (default 0); identical name/sequence/quality/seed give identical output. `--non-deterministic` instead seeds from the current time. `--reorder` restores input order with `-p > 1`. — [Bowtie2 manual](https://bowtie-bio.sourceforge.net/bowtie2/manual.shtml)
- Pairing bounds `-I`/`-X` are fixed user parameters (defaults 0 and 500), not estimated from data; wider range is slower. — [Bowtie2 manual](https://bowtie-bio.sourceforge.net/bowtie2/manual.shtml)

**strobealign** (see Q2 for details)
- Current code: insert-size distribution object created per chunk inside `map_chunk`, not shared across threads and not carried across chunks; chunks are closed after `chunk_size` nucleotides (hidden option, default 1,000,000, counting R1+R2), so boundaries depend on input and `chunk_size` only; RNG is `Rng::with_seed(0)` per chunk; writer restores chunk order. Implication from code: SAM/PAF independent of thread count but dependent on `chunk_size`. — [strobealign main.rs](https://github.com/ksahlin/strobealign/blob/main/src/main.rs)
- Changelog: v0.8.0 (2023-02-01) "Deterministic output: Mapped reads are now output in the order that they had in the input" (#121); v0.9.0 fixed an uninitialized variable that "could lead to nondeterministic results"; v0.12.0 (2023-11) assigns multimappers randomly among candidates to reduce bias. — [strobealign CHANGES.md](https://github.com/ksahlin/strobealign/blob/main/CHANGES.md)

**Other tools**
- BBMap (secondary, forum): a SEQanswers post states BBMap is always nondeterministic in paired-end mode with multiple threads because the insert-size average is computed per thread; suggested workarounds were `threads=1` or mapping as single-end and re-pairing. — [SEQanswers BBMap thread](https://www.seqanswers.com/forum/bioinformatics/bioinformatics-aa/35652-bbmap-aligner-for-dna-rnaseq-is-now-open-source-and-available-for-download?p=290145) (not verified in BBMap docs)
- Illumina DRAGEN (v3.8 docs): with `--enable-sampling`, at start the software runs a sample of up to 100,000 pairs through the aligner, computes the insert-length distribution, then uses those statistics for all pairs (Gaussian pair model); user may instead supply mean/sd/quartiles. — [DRAGEN v3.8 Mean Insert Size Detection](https://support-docs.illumina.com/SW/DRAGEN_v38/Content/SW/DRAGEN/GPipelineMeanIns_fDG.htm)
- DRAGEN v4.3+: reported insert-length QC metrics use all MAPQ>=20 properly paired pairs in the read group, whereas the log reports metrics only for the first ~2M DNA pairs (~100K RNA). — [DRAGEN v4.3 QC metrics](https://help.dragen.illumina.com/product-guides/dragen-v4.3/dragen-dna-pipeline/qc-metrics-reporting)

### Inferences
- Five patterns of cross-read adaptive state appear in practice, with different reproducibility contracts:
  1. No cross-read state (Bowtie2, minimap2 pairing): output is a function of (read, reference, options); thread- and batch-invariant by construction; tie-breaks are seeded by per-read content (Bowtie2: name+seq+qual; minimap2: name, or not even that with `--no-hash-name`).
  2. Sample-then-freeze (DRAGEN's first 100k pairs; strobealign's read-length estimate from the first 500 records): deterministic given the input's prefix; thread-invariant; but a reordered or subsampled input can change all downstream output.
  3. Per-epoch statistics on input-defined boundaries (strobealign chunks of 1 Mnt; BWA-MEM with fixed `-K`): thread-invariant but the epoch size becomes a de facto scientific parameter that must be reported (CCDG pins `-K 100000000`; Parabricks needs matching `-K`).
  4. Per-epoch statistics on thread-dependent boundaries (BWA-MEM default `-K` = 10 Mbp x threads): deterministic per thread count only.
  5. Per-thread running state (BBMap, per forum): nondeterministic.
- For CERTA's "byte-identical across thread count, batch size, CPU vs GPU" claim, only patterns 1-3 are compatible, and pattern 3 only if CERTA's adaptation epoch is decoupled from its scheduling batch (BWA conflates the two; bwa-mem2's ERT advice to use `-K 1000000` for speed shows the conflation forces a speed/reproducibility trade-off).
- bwa-mem3's SIMD-width-dependent `XS` bug is a reminder that CPU-vs-GPU identity can be broken by uninitialised padding in vectorised kernels, independent of any adaptivity.

### Gaps
- I did not find a Heng Li blog post specifically on determinism; his statements found are in GitHub issue #121 and (secondhand) Biostars.
- I did not verify in minimap2's caller code how `max_gap_ref` is set for paired-end `sr` (from `-F`/`-r`), only that `pe.c` uses no estimated distribution. No primary minimap2 statement on thread invariance was found.
- BBMap's behaviour is only from a forum post; Sentieon's BWA determinism claims could not be located.
- DRAGEN docs do not say whether the sampling step is deterministic across runs/hardware.

## Q2. Strobealign: parameters chosen from the read length estimated on the first reads; how it handles this; what the paper says

### Takeaway
Strobealign estimates read length once, before mapping, from the first 500 records, and picks one of several pre-optimized seed (strobemer/syncmer) parameter sets by canonical read length (50, 75, 100, 125, 150, 250, 400 in the current README). Because the index is built with those parameters, the index itself is tied to the read-length class; `-r` overrides the estimate and is needed when pre-building an index (`--create-index`). This makes output a function of the input's first 500 records (not of threads). The 2022 paper describes the same mechanism (with read-length thresholds) and reports large speedups, but says little about determinism.

### Cited Findings
- README: "The average read length of the input is normally estimated from the first 500 reads"; strobealign uses pre-defined parameter sets optimized for different read lengths, choosing the one whose canonical read length is close to the input's average; canonical read lengths are 50, 75, 100, 125, 150, 250 and 400. `-r` = mean read length, "overrides the read length estimated from the input file(s)", "usually only required in combination with `--create-index`." — [strobealign README](https://github.com/ksahlin/strobealign)
- Code (current Rust main branch): `estimate_read_length(&reads_reader.peek(500)?)` runs once before threads start; it averages sequence lengths (mean); the value is passed read-only to `SeedingParameters::new(read_length)`; ignored when `-P` is set (uses `SeedingParameters::noisy()`). — [strobealign main.rs](https://github.com/ksahlin/strobealign/blob/main/src/main.rs)
- Paper (Sahlin, Genome Biology 23:260, Dec 2022): "The median read length ... is estimated from the first 500 reads in the read input"; parameter tuple (k, s, p, l, u) changes at read-length thresholds 75, 125, 175, 275 and 375 nt (e.g., k from 20 to 22 above 275 nt; k=23, s=6 above 375 nt); w_min/w_max derived from k/(k-s+1) plus offsets; parameters set "based on experimental evaluation of accuracy and runtime." — [Sahlin 2022, PMC9753264](https://pmc.ncbi.nlm.nih.gov/articles/PMC9753264)
- Note the conflict: paper says median, README says average, current code computes a mean. — [paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC9753264); [README](https://github.com/ksahlin/strobealign); [main.rs](https://github.com/ksahlin/strobealign/blob/main/src/main.rs)
- Canonical-length set has changed over versions: v0.13.0 (2024-03) added a new canonical read length 75 and re-optimized parameters for read length 50; v0.8.0 fixed read-length estimation on files with few reads. — [strobealign CHANGES.md](https://github.com/ksahlin/strobealign/blob/main/CHANGES.md)
- Insert-size handling in code: `InsertSizeDistribution` starts from a prior mu=300, sigma=100 (variance 10,000), ignores inserts >= 2000, and updates mean and SSE online per accepted pair (Welford-style); instantiated fresh per chunk. — [strobealign insertsize.rs](https://github.com/ksahlin/strobealign/blob/main/src/insertsize.rs); [main.rs](https://github.com/ksahlin/strobealign/blob/main/src/main.rs)
- Paper on pairing: joint pair scoring "based on expected insert size (similar to BWA-MEM)" with a cutoff at mu+10 sigma; the estimation procedure is not described. 2022 version parallelized by splitting reads into batches of 1 million reads (OpenMP). Paper does not state whether strobealign output is deterministic. — [Sahlin 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9753264)
- Paper speed/accuracy: about 7x faster than BWA-MEM for 100-250 nt paired-end reads; 5-10x faster than minimap2 on the REPEATS dataset for reads >= 150 nt; caveats: all tools at defaults; on maize and rye strobealign does not reach BWA-MEM accuracy at 150/200 nt; not recommended for 50-75 nt reads (2022 version). — [Sahlin 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9753264)
- Successor: multi-context seeds (Tolstoganov, Martin, Buchin, Sahlin; bioRxiv Oct 2024; Genome Biology 2026, cited for strobealign >= v0.17.0): strobemers whose strobe hashes are partitioned in the seed hash, enabling a cache-friendly search for full and partial matches; reported higher accuracy with no extra memory and little runtime cost. — [MCS preprint](https://www.biorxiv.org/content/10.1101/2024.10.29.620855.full.pdf); [Zenodo record](https://zenodo.org/records/18634064); [README citations](https://github.com/ksahlin/strobealign)

### Inferences
- Strobealign's design is a clean "sample-then-freeze" + "per-chunk reset" model: the input-dependent decision (read-length class) is made once, logged ("Estimated read length"), overridable (`-r`), and changes the index; the running statistic (insert size) is reset at boundaries defined by input bases, not by threads, and the RNG is reseeded per chunk. This is the closest existing template for a reproducible adaptive aligner.
- For CERTA, the analogue would be: any pre-run decision (e.g., seed/filter parameters by read-length class) is a deterministic function of a fixed-size input prefix and is written to the output header; any running statistic is reset at fixed input-defined epochs. Unlike strobealign, CERTA's certificates make the reported optimum independent of these choices, so only tie-breaking and uncertified fields need protection.

### Gaps
- No strobealign documentation explicitly states thread-count invariance; the conclusion is from reading current code, not a tested claim. Older C++ versions (<= v0.16) may have handled insert-size state differently; not checked.
- The paper does not quantify how much accuracy/speed is lost when the read-length estimate is wrong (e.g., mixed-length or trimmed inputs).

## Q3. Presets and auto-tuning: Bowtie2/minimap2 presets, data-driven preset selection, adaptive seeding (LAST, GEM, SMEMs), learned indexes (BWA-MEME, Sapling, LISA), ML-predicted MAPQ/difficulty

### Takeaway
Mainstream presets (Bowtie2 `--very-fast` ... `--very-sensitive`, minimap2 `-x sr/map-ont/map-hifi/lr:hq/splice`) are static parameter bundles chosen by the user, not inferred from data. Data-driven adaptation that does exist is mostly (a) per-read effort/seed adaptation using only the read and the index (Bowtie2 `-D/-R`, read-length functions `-i`, `--score-min`; LAST adaptive seeds; GEM region-based adaptive filtering; minimap2 second-round chaining), (b) one-shot input sampling (strobealign read length, DRAGEN insert size), (c) reference-learned models that accelerate exact lookups without changing output (BWA-MEME, LISA, Sapling), and (d) per-sample learned MAPQ (Qtip). No mainstream aligner I found auto-selects a full preset from the observed error profile.

### Cited Findings
**Static presets and per-read functions**
- Bowtie2 end-to-end presets: `--very-fast` = `-D 5 -R 1 -N 0 -L 22 -i S,0,2.50`; `--fast` = `-D 10 -R 2 -N 0 -L 22 -i S,0,2.50`; `--sensitive` (default) = `-D 15 -R 2 -N 0 -L 22 -i S,1,1.15`; `--very-sensitive` = `-D 20 -R 3 -N 0 -L 20 -i S,1,0.50`; local-mode analogues exist; since v2.4.0 individual values can be overridden. — [Bowtie2 manual](https://bowtie-bio.sourceforge.net/bowtie2/manual.shtml)
- Bowtie2 per-read adaptivity: `-D` = up to N consecutive seed-extension attempts can "fail" (no new best or second-best) before moving on; `-R` = max re-seeds for reads with repetitive seeds, where a read is repetitive if total seed hits / seeds aligned at least once > 300; `-i` seed interval and `--score-min` are functions of read length (types C, L, S=sqrt, G=ln; e.g., `S,1,1.15` = 1+1.15*sqrt(len); `--score-min` default L,-0.6,-0.6 end-to-end, G,20,8 local). Bowtie2 "does not guarantee that the alignment reported is the best possible in terms of alignment score." — [Bowtie2 manual](https://bowtie-bio.sourceforge.net/bowtie2/manual.shtml)
- minimap2 presets: `map-ont` (default, ~10% error), `lr:hq` (<1% error), `map-hifi` (differs from lr:hq only in scoring), `sr`, `splice`, `splice:hq`, `splice:sr`. Presets are chosen by the user. — [minimap2.1 man page](https://github.com/lh3/minimap2/blob/master/minimap2.1)

**Adaptive seeding using only read + index**
- LAST adaptive seeds (Kielbasa et al.; Genome Research 21(3):487-493, 2011): seeds vary in length and are lengthened until the number of matches in the target is <= a frequency threshold f; because rare matches are selected, the number of matches and runtime grow linearly rather than quadratically with sequence length. — [Kielbasa et al. 2011](https://genome.cshlp.org/content/21/3/487); [PMC3044862](https://pmc.ncbi.nlm.nih.gov/articles/PMC3044862)
- GEM mapper (Marco-Sola, Sammeth, Guigo, Ribeca; Nature Methods 9:1185-1188, 2012), "region-based adaptive filtering": pick a threshold t (max candidates per filtering segment, the "computational budget"); scan the read backward in the FM-index, extending the current region one base at a time while counting candidates; when the count falls below t, close the region and start a new one. This guarantees per-region candidates < t but not the number of regions; if >= m+1 regions are found, exact region matches suffice (pigeonhole) for all matches up to m mismatches; otherwise regions must be searched with errors, at higher cost. The authors note how to choose filtering optimally per read was "an open problem." — [GEM paper, Online Methods](https://doi.org/10.1038/nmeth.2221)
- GEM claims searches are exhaustive within the specified distance regardless of alignment parameters (respects strata boundaries); "fast/hyperfast" modes skip reads for which the method cannot find enough regions, but reads they do align are aligned exhaustively. — [GEM paper](https://doi.org/10.1038/nmeth.2221)
- minimap2 `--sr` second chaining round with a higher occurrence threshold when no good chain is found (per-read fallback). — [minimap2.1 man page](https://github.com/lh3/minimap2/blob/master/minimap2.1)

**One-shot input sampling**
- strobealign read-length class from the first 500 records (Q2); DRAGEN insert-size distribution from up to 100,000 pairs at start (Q1). — [strobealign README](https://github.com/ksahlin/strobealign); [DRAGEN v3.8](https://support-docs.illumina.com/SW/DRAGEN_v38/Content/SW/DRAGEN/GPipelineMeanIns_fDG.htm)

**Learned indexes (adapt to the reference, output-preserving)**
- BWA-MEME (KAIST; Bioinformatics 38(9), 2022, doi 10.1093/bioinformatics/btac137): first full short-read aligner using learned indices for exact-match search in seeding (suffix-array search); up to 3.45x seeding throughput vs BWA-MEM2 via fewer instructions, memory accesses and LLC misses; reports SAM output identical to BWA-MEM2. — [BWA-MEME bioRxiv](https://www.biorxiv.org/content/10.1101/2021.09.01.457579v1.full.pdf); [KAIST record](https://dspace.kaist.ac.kr/handle/10203/296423)
- Sapling (Kirsche, Das, Schatz; Bioinformatics 37(6):744-749, 2021): learned piecewise-linear model to speed up suffix-array lookups; more than 2x faster with <1% extra memory. — [Sapling, doi 10.1093/bioinformatics/btaa911](https://doi.org/10.1093/bioinformatics/btaa911)
- LISA in bwa-mem2: up to 4.5x faster seeding than bwa-mem2 with "exact same output." — [bwa-mem2 README](https://github.com/bwa-mem2/bwa-mem2)

**Per-sample learned mapping quality**
- Qtip (Langmead; Genome Biology 2017, doi 10.1186/s13059-017-1290-3): after observing the input reads and their alignments, Qtip simulates reads mimicking the input's length, quality, gap and edit distributions, aligns them, and trains an ensemble tree model to predict MAPQ; aligners (Bowtie 2, BWA-MEM, SNAP) were modified only to emit features; predictions reported better than the aligners' own MAPQ. MOSAIK used a neural network for MAPQ trained ahead of time on user-supplied simulated reads. — [Qtip, PMC5557537](https://pmc.ncbi.nlm.nih.gov/articles/PMC5557537)

**Other**
- Accel-Align (Yan, Chaturvedi, Appuswamy; BMC Bioinformatics 22, 2021): seed-embed-extend, randomized embedding from edit to Hamming space; 3-12x faster than state-of-the-art aligners at comparable accuracy. — [Accel-Align, PMC8139006](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC8139006/)

### Inferences
- Adaptation that reads only (read, index) is the dominant and safest form: it is per-read, so thread/batch/device invariant by construction. GEM's region-based adaptive filtering is especially relevant to CERTA because it adapts the filter partition per read while keeping an exhaustiveness guarantee via pigeonhole, which is the same "sound for any parameter setting" property CERTA's certificates have.
- Learned indexes show a second safe pattern: a model that only accelerates an exact lookup and is followed by exact correction leaves output bit-identical (BWA-MEME/LISA claim identity with bwa-mem2).
- Qtip-like per-sample models are the opposite extreme: the output field (MAPQ) depends on a whole-sample model, which CERTA would have to treat as an uncertified, separately versioned annotation if adopted.
- I found no aligner that infers a full preset (e.g., `sr` vs `map-hifi`) from observed error rate; this seems to be a gap CERTA could fill, but the closest precedents are strobealign's read-length classes and Bowtie2's read-length functions.

### Gaps
- No primary source found on SMEM-based "adaptivity" as a named technique, OptiFilter, or BitMapper's adaptive filtering.
- Accel-Align's handling of randomness in the embedding (fixed seed? per-read?) and its determinism were not checked.
- LISA's own paper (Ho et al.) was not retrieved; only the bwa-mem2 README claim.
- No source on ML-predicted per-read "difficulty" used to steer search effort in a mainstream aligner was found.

## Q4. Online/adaptive parameter control in exact or fully sensitive search: filtration thresholds (RazerS/Yara), q-gram and pigeonhole filters with adaptive parts (Hobbes, OSS), search schemes (Kucherov et al., Kianfar et al., dynamic partitioning)

### Takeaway
The fully sensitive / exact-search literature has a mature notion of choosing filter parameters to minimize work while keeping a correctness guarantee: RazerS picks q-gram filter parameters from a user-specified minimum sensitivity; Hobbes and the Optimal Seed Solver choose per-read seed partitions by dynamic programming over index frequencies; search schemes (Kucherov et al.) and optimum search schemes (Kianfar et al., MIP) fix the search strategy offline; dynamic partitioning (Renders et al., Columba) adapts each pattern's partition at run time for any search scheme while still retrieving all occurrences. All of these adapt per pattern using only the pattern and index, so the reported set of matches is invariant; the adaptation changes only the cost.

### Cited Findings
- RazerS (Weese, Emde, Rausch, Doring, Reinert; Genome Research 19(9), 2009): read mapper "with sensitivity control" based on counting q-grams. RazerS 3 (Weese, Holtgrewe, Reinert; Bioinformatics 28(20), 2012): adds a seed-based (pigeonhole) filter "optimized for low error-rates with controllable sensitivity," banded Myers bit-vector verification, multicore support; full sensitivity under the Rabema definition. — [SeqAn RazerS 3 page](https://www.seqan.de/apps/razers3.html)
- RazerS 3 man page: fully sensitive mapper based on k-mer counting and seeding filters; it "chooses filter parameters" from a user-defined minimal sensitivity (runtime/sensitivity trade-off). — [razers3(1) Debian man page](https://dyn.manpages.debian.org/trixie/seqan-apps/razers3.1)
- Yara (SeqAn; successor of Masai): `-e` error rate (default 5%, 0-10), `-s` strata rate (suboptimal alignments within this many percent errors of the optimum, default 0), `-y` sensitivity `low/high/full` (default high); `full` finds all considered alignments at runtime cost, `low` gives up that guarantee for speed. — [yara_mapper(1) man page](https://dyn.manpages.debian.org/buster/seqan-apps/yara_mapper.1); [SeqAn Yara page](https://www.seqan.de/apps/yara.html)
- Masai (Siragusa et al., arXiv preprint 2012): speed from approximate seeds and multiple backtracking; approximate seeds improve filtration specificity while keeping sensitivity. Siragusa's thesis: Yara generalizes this to report all co-optimal or suboptimal locations within a user-defined error rate. — [Masai arXiv:1208.4238](https://arxiv.org/abs/1208.4238); [Siragusa thesis](https://refubium.fu-berlin.de/handle/fub188/11364)
- Hobbes: considers all possible partitions of the read into grams and uses dynamic programming to pick the one minimizing the sum of gram frequencies (summary via search; OSS paper compares against Hobbes's "Optimal Prefix Selection"); Hobbes2 (BMC Bioinformatics 2014) adds extra prefix q-grams so at least two seeds must match exactly (pigeonhole), filtering candidates hit by fewer seeds. — [Hobbes2, PMC3927682](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC3927682/); [Hobbes3, ICDE 2016](https://chenli.ics.uci.edu/files/icde2016-hobbes3.pdf)
- Optimal Seed Solver (Xin et al.; Bioinformatics 32(11):1632-1642, 2016): DP algorithm that provably finds the least frequently occurring set of non-overlapping seeds in a read (preserving pigeonhole sensitivity); 3-fold reduction in average seed frequency over the best previous seed-selection optimizations. — [OSS, doi 10.1093/bioinformatics/btv670](https://doi.org/10.1093/bioinformatics/btv670); [arXiv 1506.08235](https://arxiv.org/abs/1506.08235)
- AMAS (2015 preprint) optimizes partition and filtration of adaptive seeds for read mapping (title-level evidence only). — [AMAS arXiv:1502.05041](https://arxiv.org/pdf/1502.05041)
- Search schemes (Kucherov, Salikhov, Tsur; CPM 2014, LNCS 8486:222-231; Theoretical Computer Science 638:145-158, 2016): formalism for bidirectional FM-index search strategies generalizing Lam et al.'s k+1 equal parts to arbitrary k and unequal partitions into more than k+1 parts, with a probabilistic efficiency measure. — [arXiv 1310.1440](https://arxiv.org/abs/1310.1440)
- Optimum search schemes (Kianfar, Pockrandt, Torkamandi, Luo, Reinert; 2017/2018): mixed-integer program finding optimal schemes for Hamming distance with a given number of parts; for 101 bp Illumina reads with two errors, ~35x faster than standard backtracking; for <= 2 errors, index-only search comparable to leading aligners that verify with DP. — [arXiv 1711.02035](https://arxiv.org/abs/1711.02035); [bioRxiv 10.1101/301085](https://www.biorxiv.org/content/10.1101/301085.full.pdf)
- Dynamic partitioning (Renders, Marchal, Fostier; iScience 24(7), 2021): algorithm to dynamically partition search patterns, applicable to any search scheme, that substantially shrinks the search space; implemented in Columba; retrieves all occurrences of 100,000 Illumina reads and their reverse complements within edit distance 4 in the human genome in under 3 minutes on one CPU core. — [Renders et al. 2021, doi 10.1016/j.isci.2021.102687](https://doi.org/10.1016/j.isci.2021.102687) (abstract via Europe PMC)
- GEM region-based adaptive filtering (see Q3) is the same idea applied in a production mapper. — [GEM paper](https://doi.org/10.1038/nmeth.2221)

### Inferences
- These methods separate "what is guaranteed" (all matches within distance k, or a sensitivity target) from "how it is searched" (partition, seed lengths, order). This maps directly onto CERTA: certificates guarantee optimality for any parameter setting, so adaptive parameters can be treated as pure search-strategy choices, like a dynamic search scheme.
- The prior art adapts per pattern from index statistics; none of the cited exact-search tools adapts across reads using statistics from earlier reads. A CERTA design that learns from earlier reads (e.g., the distribution of optimal scores or certificate tightness) appears to be new relative to this literature, and it is where reproducibility must be engineered (Q1 patterns 2-3).
- RazerS's "choose filter parameters to meet a sensitivity target" is the closest precedent for a parameter-selection rule with a stated guarantee; CERTA's stronger guarantee (per-read optimality certificate) means it can use parameter choices that would otherwise be unsafe.

### Gaps
- Original Hobbes paper text was not retrieved; the DP description is from secondary summaries.
- No primary source found for "q-gram lemma filters with adaptive q" in RazerS beyond "chooses filter parameters"; the exact parameter-selection procedure (precomputed sensitivity tables) was not verified.
- OptiFilter, BitMapper and Myers-style adaptive filters were not found in this pass.
- Renders et al. full text (exact speedup over static partitioning) was not retrieved, only the abstract.

## Q5. Reported speed gains from adaptation and documented accuracy/reproducibility caveats; what carries over to a certified aligner

### Takeaway
Reported gains from adaptive or data-informed search range from about 2x (GEM hyperfast, Sapling) through 3-4.5x (OSS seed frequency, BWA-MEME and LISA seeding) to 35x (optimum search schemes vs backtracking); strobealign's read-length-tuned seeds give ~7x over BWA-MEM. The documented caveats are of two kinds: accuracy loss when adaptation is heuristic (Bowtie2 no best-alignment guarantee; GEM fast modes skip hard reads; strobealign weaker on some genomes and short reads) and reproducibility loss when cross-read statistics are tied to thread-dependent batches (BWA-MEM, Parabricks, BBMap). Output-preserving adaptations (learned indexes, exhaustive adaptive filtering) report identity with the non-adaptive tool.

### Cited Findings
- GEM: ~40 million single-end reads per CPU core-hour at BWA defaults; 18x faster than mrsFAST (no indels, all strata); 6x faster than Bowtie/Bowtie2 in first-match mode; 5x faster than default BWA while reporting all matches; the basic fast mode maps ~0.2% fewer reads than full mode but runs twice as fast. — [GEM paper](https://doi.org/10.1038/nmeth.2221)
- LAST adaptive seeds: linear instead of quadratic growth of matches/runtime with sequence length. — [Kielbasa et al. 2011](https://genome.cshlp.org/content/21/3/487)
- OSS: 3-fold reduction in average seed frequency. — [OSS](https://doi.org/10.1093/bioinformatics/btv670)
- Optimum search schemes: ~35x vs backtracking (101 bp, 2 errors). — [Kianfar et al.](https://arxiv.org/abs/1711.02035)
- Columba with dynamic partitioning: 100k reads + RC, edit distance 4, human genome, < 3 min on one core. — [Renders et al. 2021](https://doi.org/10.1016/j.isci.2021.102687)
- BWA-MEME: up to 3.45x seeding throughput, identical output to BWA-MEM2; LISA up to 4.5x seeding; ERT 10-30% faster; bwa-mem2 1.3-3.1x over bwa. — [BWA-MEME](https://www.biorxiv.org/content/10.1101/2021.09.01.457579v1.full.pdf); [bwa-mem2 README](https://github.com/bwa-mem2/bwa-mem2)
- Sapling: >2x suffix-array query speedup, <1% memory. — [Sapling](https://doi.org/10.1093/bioinformatics/btaa911)
- strobealign: ~7x faster than BWA-MEM (100-250 nt PE); lower accuracy than BWA-MEM on maize/rye at 150/200 nt; not recommended for 50-75 nt (2022). — [Sahlin 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9753264)
- Reproducibility caveats: BWA-MEM output changes with thread count unless `-K` is fixed (issue #121, man page); equivalence claims hold only at fixed batch size (bwa-mem3); GPU fq2bam needs matching `-K` in paired-end mode; CCDG standard pins `-K 100000000`. — [bwa issue #121](https://github.com/lh3/bwa/issues/121); [bwa-mem3 docs](https://bwa-mem3.readthedocs.io/en/latest/whats-different/equivalence.html); [Parabricks](https://docs.nvidia.com/clara/parabricks/latest/Documentation/ToolDocs/man_fq2bam.html); [CCDG](https://github.com/CCDG/Pipeline-Standardization/blob/master/PipelineStandard.md)
- Tie-breaking caveat: Bowtie2 and minimap2 derive tie-breaks from per-read content (name/sequence/quality + seed), bwa from input position (secondhand); strobealign v0.12 randomizes multimapper placement with a per-chunk seeded RNG. — [Bowtie2 manual](https://bowtie-bio.sourceforge.net/bowtie2/manual.shtml); [minimap2.1](https://github.com/lh3/minimap2/blob/master/minimap2.1); [strobealign CHANGES.md](https://github.com/ksahlin/strobealign/blob/main/CHANGES.md); [main.rs](https://github.com/ksahlin/strobealign/blob/main/src/main.rs)

### Inferences
Ideas that carry over to CERTA (inferences from the above, not claims made by any source):
- Separate the guaranteed output from the adaptive strategy. CERTA's certificate makes the optimal score parameter-independent; what can still drift is (i) which co-optimal alignment is reported, (ii) uncertified fields (MAPQ, secondary/supplementary records, XS-like tags, pairing decisions if they use estimated insert-size priors), and (iii) the certificate's own content if it records the bounds used. Each must be canonicalized: a total order on co-optimal alignments that depends only on (read, reference, scoring), and a canonical certificate form or a certificate kept outside the byte-identity contract.
- Make adaptation state a deterministic function of input order, never of execution order. Use strobealign's pattern: decisions from a fixed-size input prefix (sample-then-freeze), or epochs of a fixed number of input bases/reads at which parameters may change (like `-K`), with the epoch size independent of thread count, batch size and device. Decouple the scheduling batch (throughput) from the statistics epoch (reproducibility), which BWA-MEM conflates.
- Lagged update: parameters for epoch e+1 computed only from completed epochs <= e (or e-1, to allow pipelining) so GPU/CPU workers can run ahead without races; reduce statistics with an order-independent or fixed-order reduction (strobealign's abundance sums show floating-point sums in arrival order are not associative).
- Prefer per-read adaptation from (read, index) wherever possible (GEM region profile, LAST adaptive seeds, OSS, dynamic search-scheme partitioning, Bowtie2-style read-length functions): these give speed without any cross-read state.
- Record the full parameter trace (epoch size, initial values, per-epoch parameters or a hash) in the output header so runs are auditable, mirroring strobealign's logged read-length estimate and `-r` override; provide an override flag that freezes all parameters for regulatory pipelines (cf. CCDG pinning `-K`).
- Watch device-specific hazards unrelated to adaptivity (bwa-mem3's SIMD-width-dependent XS tag; Parabricks tag ordering/rounding).

### Gaps
- No source quantifies the speed benefit of cross-read (online) adaptation specifically, as opposed to per-read adaptation or offline tuning; BWA-MEM's and DRAGEN's insert-size estimation is justified for accuracy, not speed.
- No aligner documentation found that publishes a formal reproducibility contract for adaptive parameters beyond "fix -K" (bwa) and "fixed batch size" (bwa-mem3).
- Accuracy impact of BWA-MEM's thread-dependent output (how many records change, which fields) is documented only anecdotally (e.g., a Biostars user reporting ~50,000 more mapped reads at a different thread count, via search summary) and was not verified.
